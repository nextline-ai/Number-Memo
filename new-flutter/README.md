# 품번메모 · Flutter

Android와 Windows/Linux PC를 위한 품번메모 클라이언트입니다. Apple 기기용 기존 앱은 `../native-ios`에 있으며, 이 프로젝트와 별도로 유지합니다. 화면은 흑백·회색의 한국어 Material 3로 구성하고 휴대전화에서는 하단 탐색, 넓은 화면에서는 사이드바를 사용합니다.

## 개발 환경

기준 SDK는 **Flutter 3.47.6 / Dart 3.13.5**이며 `.fvmrc`에 Flutter 버전을 고정했습니다. [Flutter 3.47.6 소스](https://github.com/flutter/flutter/tree/3.47.6)를 기준으로 합니다.

FVM이 설치된 환경에서 이 디렉터리로 이동한 뒤 실행합니다.

```sh
fvm install 3.47.6
fvm flutter doctor -v
fvm flutter pub get
fvm flutter devices
```

같은 버전의 Flutter SDK를 직접 설치했다면 아래 명령에서 `fvm flutter`를 `flutter`로 바꿔도 됩니다. 플랫폼별 네이티브 도구 설치 상태는 `flutter doctor`로 확인합니다.

| 대상 | 실행 | 빌드 환경 |
| --- | --- | --- |
| Android | `fvm flutter run -d <ANDROID_DEVICE_ID>` | Android SDK, JDK 17, 연결된 기기 또는 에뮬레이터 |
| Windows | `fvm flutter run -d windows` | Windows 호스트 및 Visual Studio의 C++ 데스크톱 개발 도구 |
| Linux | `fvm flutter run -d linux` | Linux 호스트 및 Flutter Linux 데스크톱 빌드 도구 |
| macOS 개발 확인 | `fvm flutter run -d macos` | macOS 호스트 및 Xcode |

Windows와 Linux 빌드는 각각 해당 운영체제에서 실행해야 합니다. `ios/`, `web/` 폴더는 생성된 플랫폼 틀이며 이번 구현의 지원 대상이 아닙니다. 특히 데이터 저장과 파일 작업에 `dart:io`를 사용하므로 웹 실행을 지원하지 않습니다.

## 구현한 기능

- 책/이미지 모드의 보관함 → 탐색 → 작가 → 설정 탭. 보관함 안에서 작품 목록과 폴더를 전환합니다.
- Hitomi 작품 번호 및 링크 여러 개 추가, 작품 정보 조회, 키워드·작가·태그·언어 검색, 최신/인기 목록과 추가 페이지 조회.
- Android의 다른 앱에서 텍스트·링크를 공유하면 작품 추가 창에서 내용을 확인하고 저장할 수 있습니다.
- Safebooru 기본 서버와 Danbooru/Gelbooru/Moebooru 계열 공개 API 서버 등록, 활성화, 제외 태그, 여러 서버 검색, 수위 필터 및 태그 제안.
- 작품 저장, 제목·메모 편집, 폴더 분류, 작가 저장, 보관함 검색과 정렬, 검색 기록과 기록 지우기.
- 보관함 다중 선택, 폴더 일괄 추가/교체, 링크·번호 일괄 복사, 책 메타데이터 일괄 갱신, 일괄 삭제와 실행 취소. 미분류·최근 읽은 작품 필터와 이어 읽기 카드.
- 상세 화면의 태그 검색·복사·기본 검색 태그 추가·제외 토글. Booru 제외 규칙은 줄별 OR, 같은 줄의 AND, `-태그`, `*` 와일드카드, `rating:`, `id:`를 지원합니다.
- 책 페이지/이미지 보기, 읽던 위치 저장, 연속 보기, 오른쪽에서 왼쪽으로 읽기, 양쪽 탭 이동, 두 번 탭 확대, 가로 맞춤, 페이지 번호 입력, 썸네일 목록, 길게 눌러 보관함 저장.
- 현재 이미지·원본·표지 파일 저장과 뷰어 이미지 공유(Android/Windows/macOS). Android는 시스템 파일 저장 창을, PC는 저장 위치 선택 창을 사용합니다. Linux는 파일 저장을 지원합니다. 동영상 재생은 외부 앱 또는 브라우저에서 엽니다.
- 시스템/밝은/어두운 흑백 테마, 목록 열 수, 책 사이트 주소, 책 기본 검색·제외 태그, 리더 설정. 폴더는 저장된 원래 색상으로 표시하고 기존 iOS 앱의 28색 팔레트에서 선택합니다.
- PC 단축키: Ctrl/Cmd+K 검색, Ctrl/Cmd+N 추가, Ctrl/Cmd+1~4 보관함·탐색·작가·설정 이동, Ctrl/Cmd+Shift+M 모드 전환, F1 도움말. 뷰어에서는 화살표·PageUp/PageDown·Home/End로 페이지를 이동합니다.
- JSON 백업 내보내기와 병합 가져오기. Android에서는 시스템 공유 화면으로 내보내고 데스크톱에서는 저장 위치를 선택합니다.

보관함과 메모는 로컬에 보존합니다. 원본 이미지 전체를 오프라인 다운로드하거나 기기 간 자동 동기화하는 기능은 포함하지 않습니다. 탐색 및 원본 열기는 인터넷과 해당 서버의 공개 API 접근 가능 여부에 따라 동작합니다. 로그인·API 키·브라우저 확인이 필요한 서버에는 오류와 원본 사이트 열기 동작을 제공합니다.

## 저장과 백업

`path_provider`의 애플리케이션 지원 디렉터리 아래 `number_memo/library.json`에 저장합니다. 저장 요청을 순서대로 처리하고, 같은 디렉터리의 임시 파일에 기록·flush한 뒤 rename합니다. 디스크 기록이 실패하면 화면의 데이터도 이전 상태를 유지합니다. 기존 파일이 손상되어 있으면 자동 초기화하지 않고 시작 오류를 표시하여 원본을 보존합니다.

Flutter 백업은 `format: "number-memo-flutter"`, `version: 1` 형식입니다. 기존 데이터는 유지하고 새로운 항목을 합칩니다. 같은 항목의 메모·폴더 연결은 합치며 읽기 위치는 두 백업에 최근 열람 시간이 있으면 더 최근 위치를 유지하며, 시간이 없는 구형 백업은 더 진행된 값을 유지합니다. 이미 변경한 설정과 등록 서버 설정은 보존하고(제외 규칙은 병합), 같은 서버 주소와 항목은 중복 없이 합칩니다. 초기 상태의 보관함으로 가져올 때만 백업의 앱 설정을 복원합니다.

기존 iOS 앱의 **version 2 JSON 백업은 가져오기만 지원**합니다. 책, 메모, 폴더, 작가를 가져오며 그룹은 `group:이름`으로 표현합니다. Flutter에서 내보낸 파일을 기존 iOS 앱으로 다시 가져오는 호환성은 제공하지 않습니다. 기존 앱의 작가별 메모, 사용자 지정 표지 페이지와 같은 모든 필드를 그대로 옮기지는 않습니다.

설정에서 **Violet SQLite**와 **Anime Boxes `.abbj`**도 가져올 수 있습니다. 가져오기 전에 항목·폴더·작가 개수를 확인하며 기존 데이터에 병합합니다.

- Violet: `user.db`의 즐겨찾기·폴더·작가를 가져옵니다. 선택적으로 `data.db`를 함께 고르면 해당 즐겨찾기의 제목·작가·태그를 채웁니다. `user.db`는 최대 256 MB, `data.db`는 최대 4 GB이며 원본 데이터베이스는 읽기 전용으로 처리합니다. WAL/journal 파일이 남은 사용 중인 데이터베이스는 Violet을 종료하고 완전한 사본을 준비해야 합니다. `data.db`가 없으면 번호로 가져온 뒤 작품 정보 새로고침을 사용할 수 있습니다.
- Anime Boxes: 백업 버전 1.0의 즐겨찾기 이미지, 지원하는 공개 Booru 서버, 제외 규칙과 검색 기록을 가져옵니다. 파일은 최대 64 MB이며 지원하지 않는 서버·깨진 항목은 건너뜁니다. 로그인 자격 증명과 원본 캐시는 가져오지 않습니다.
- Android의 외부 백업 선택은 네이티브 파일 선택기에서 임시 파일로 스트리밍하므로 큰 SQLite 파일을 메모리에 한 번에 올리지 않습니다.

이미지 저장은 파일당 최대 100 MB입니다. 공유용 임시 파일은 수신 앱이 읽을 시간을 보장하기 위해 남겨두고, 24시간이 지난 파일은 다음 이미지 내보내기 때 정리합니다.

백업에는 원본 이미지 파일이 포함되지 않습니다. 앱 삭제나 데이터 정리 전에 JSON 백업을 별도로 보관하세요.

## 범위와 남은 작업

Apple 전용 OCR·번역, 내장 브라우저, 앱 내부 동영상 재생, 작품 전체의 오프라인 다운로드 관리자는 아직 구현하지 않았습니다. iOS 앱과 모든 화면·기능을 일대일로 대응시키는 프로젝트가 아닙니다.

Android `release` 빌드의 서명 설정은 현재 템플릿의 **debug 키**를 사용합니다. 배포 전 전용 서명 키와 릴리스 설정을 적용해야 합니다. macOS 배포용 서명·공증과 Windows 설치 프로그램 구성도 별도 작업입니다.

```sh
# 플랫폼에 맞는 호스트에서 실행
fvm flutter build apk --release
fvm flutter build appbundle --release
fvm flutter build windows --release
fvm flutter build linux --release
fvm flutter build macos --release
```

## 검증

2026-10-05 로컬 검증 결과: Flutter 3.47.6에서 정적 분석 오류 없이 테스트 **117개**를 통과했고, Android 디버그 APK와 macOS 디버그 앱을 빌드했습니다. Windows/Linux는 해당 호스트에서의 빌드와 실제 기기 검증이 남아 있습니다. Android 최소 버전은 API 24이며, 현재 Flutter 기본 compile/target SDK는 API 36입니다.

보관함·폴더·편집·읽던 위치·Android 공유 수신·서버별 재시도와 2,000개 항목의 지연 그리드, 흑백 테마, PC 단축키, 일괄 분류·삭제 취소, 읽기 편의, SQLite/ABBJ 변환, 서버 중복 병합, 이미지 다운로드 제한을 테스트합니다. Android API 36.1 에뮬레이터에서 APK 설치·실행과 시스템 파일 선택 → Violet SQLite 변환 → 가져오기 미리보기 → 취소 후 임시 파일 정리를 확인했습니다. Android 공유 수신과 파일 채널의 예외 처리는 모의 테스트도 포함합니다. 실제 기기의 다양한 문서 공급자·공유 앱 조합과 이미지 저장 완료 흐름은 별도 확인이 필요합니다.


```sh
fvm flutter analyze
fvm flutter test

# 데이터 저장/백업과 네트워크 파서를 개별 확인
fvm flutter test test/data_store_test.dart
fvm flutter test test/catalog_service_test.dart
```

데이터 테스트는 동시 저장, 저장 실패 후 복구, 재실행 복원, 폴더 삭제, 손상된 백업 거부 및 기존 iOS 백업 병합을 다룹니다. 네트워크 테스트는 주입한 HTTP 응답으로 페이지 요청, 메타데이터, CDN 주소, 서버별 응답 형식을 검증합니다. 테스트 통과가 모든 외부 서버의 현재 접근 가능 여부를 보장하지는 않습니다.

소스와 `pubspec.lock`을 공유하고 `.dart_tool/`, `build/`, `coverage/`, 실행 로그, 기기별 생성 파일, 개인 백업 및 서명 키는 커밋하지 않습니다. 각 플랫폼의 실제 빌드·기기 검증 결과는 실행한 환경별로 구분해서 기록해야 합니다.

`fvm flutter test tool/render_preview.dart`는 실제 보관함과 분리한 메모리 데이터로 밝은/어두운 모바일·PC UI를 그려 `build/previews/`에 PNG를 저장합니다. 한국어 화면 미리보기는 macOS 시스템 글꼴이 있을 때 가장 정확합니다.
