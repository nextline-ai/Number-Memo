# 네이티브 래퍼와 읽기 UX 구현

2026년 10월 4일. `codex/native-content-wrapper-study` 브랜치에서 웹뷰를 SwiftUI·UIKit 탐색 및 읽기 화면으로 교체하고, 전체 화면 읽기·번역·미리 받기를 추가했다. 자체 중계 서버 없이 원본 CDN에 URLSession으로 요청한다.

## 사용자 동작

읽기 화면은 상단 제목·도구·상태바를 숨기고, 나가기 제스처를 알리는 작은 상단 바를 표시한다. 화면 좌우를 탭하면 이전·다음 페이지로 이동하고, 가운데를 탭하면 퀵 메뉴를 연다. 가운데를 길게 누르면 작품을 기본 폴더에 북마크한다. 이미 저장된 작품은 중복 저장하거나 폴더를 옮기지 않는다. 두 번 탭과 핀치로 확대한다. 확대 중에는 상하좌우에 화면 절반 크기의 이동 여백을 둬 이미지의 가장자리도 화면 가운데로 옮길 수 있다. 확대 중 드래그는 이미지 이동만 하며 부모 페이지 넘김·연속 스크롤·아래로 쓸어 나가기는 잠근다. 원래 배율로 돌아오면 이전 스크롤 상태를 복원한다.

퀵 메뉴에는 북마크, 나가기, 번역, 상세정보, 전체 페이지 프리뷰, 상세설정과 페이지 번호 이동이 있다. 나가기는 작품 상세로 돌아가거나, 읽기로 바로 진입한 경우 콘텐츠 화면을 닫는다. 이미지 로딩·오류 상태에서도 탭으로 메뉴를 열 수 있다.

읽기 설정은 기기에 보존한다.

| 설정 | 동작 |
| --- | --- |
| 가로로 넘기기 / 수직으로 넘기기 / 스크롤로 보기 | UIPageViewController의 가로·세로 페이징 또는 LazyVStack 연속 스크롤 |
| 오른쪽에서 왼쪽으로 넘기기 | 가로 스와이프 및 좌우 탭의 방향 전환 |
| 한 번에 여러 페이지 | 1~4페이지를 나란히 표시. 가로·세로 페이징과 스크롤 모드 모두 지원하며 RTL에서는 페이지 배치도 반전 |
| 자동 넘기기 | 2~120초, 1초 단위. 메뉴·설정·번역·확대·백그라운드에서는 일시 정지. 마지막 묶음에서 종료 |
| 화면 좌우 탭으로 넘기기 | 탭 이동 사용 여부. 가운데 메뉴는 계속 사용 가능 |
| 하단에 퀵 메뉴 표시 | 6개 메뉴 아이콘을 계속 표시 |
| 페이지 번호 표시 | 메뉴가 닫힌 상태의 작은 페이지 표시 |
| 읽는 동안 화면 켜두기 | 읽기 종료 시 기존 자동 잠금 설정 복원 |
| 화면 어둡게 | 앱 내부 읽기 화면에만 밝기 감소 적용 |
| 미리 받을 페이지 | 끄기 / 2 / 3 / 5페이지, 기본 3페이지 |

탐색은 기존 전체 탭을 대체하며 지구본 아이콘을 사용한다. 우측 하단의 별도 버튼은 제거했다. 탐색은 보관함과 `GalleryCardLayout`, `WorkGridLayout`을 공유한다. 표지 비율·언어 배지·제목·작가 표시가 같으며 `AppEnvironment.gridColumns`의 동일한 값을 읽는다. iPad 등 넓은 화면의 기존 열 수 보정도 공유한다. 작품을 길게 누르면 북마크하고, 다시 길게 누르면 해제한다. 보관함 저장 여부와 좌측 상단 배지가 함께 갱신된다.

기존 번호·링크 열기, 언어·작가·태그별 목록, 검색, 읽던 위치 복원과 외부 브라우저 선택은 유지한다.

## 한 번 눌러 번역

기존 인앱 브라우저의 `3fa38f9` 구현은 WKWebView 화면을 캡처하고 `ImageAnalyzer`와 `ImageAnalysisInteraction`으로 Apple Live Text 이미지 번역을 실행했다. 현재 네이티브 읽기에서도 같은 VisionKit 방식을 사용한다. 웹뷰 캡처 대신 원본 페이지의 현재 보이는 영역을 최대 6000px로 디코딩해 사용한다. 앱의 줄별 TranslationSession 요청, 배경색 추정 및 번역 박스 렌더러는 제거했다. 문맥 처리·번역·원문 가리기·레이아웃은 시스템이 담당한다.

분석 중에는 작은 진행 아이콘을 표시하고 원래 페이지를 유지한다. **원본으로** 버튼으로 분석 또는 번역을 닫는다. 원하는 부분을 읽기 화면에서 확대·이동한 뒤 번역을 누르면 현재 보이는 원본 영역을 분석한다. 확대 중 퀵 메뉴를 열기 직전에 영역을 다시 읽어 이동 직후의 위치도 반영한다. 언어 선택과 다운로드 등은 Apple 이미지 번역 UI를 따른다. [Apple ImageAnalysisInteraction 문서](https://developer.apple.com/documentation/visionkit/imageanalysisinteraction).

번역 세션마다 분석은 한 번만 수행한다. 확대/이동할 때 자동 재분석·번역 재실행은 제거했다. `ImageAnalysisInteraction`은 확대되지 않는 `LiveTextCanvasView`에 붙이고, `contentView` 및 `contentsRect`로 움직이는 이미지를 연결한다. 이미지가 확대되거나 이동하면 좌표만 갱신하며 시스템 번역/인식 버튼은 화면 안에 유지한다. 시스템 레이어 위에서도 확대·이동이 되도록 공통 상위 뷰에서 두 번 탭·핀치·팬을 처리하고, 시스템 버튼에 시작한 터치는 제외한다.

이미지 번역을 직접 시작하는 공개 API는 없다. 번역 동작은 소유한 캔버스 안에서 시스템의 UIMenu 액션을 우선 찾고, 없으면 활성화된 UIControl을 찾는다. 영어·한국어·일본어·중국어 표시를 처리하며 비활성/숨김 액션은 건너뛴다. 이미 선택된 액션은 다시 눌러 번역을 끄지 않는다. OCR 완료와 버튼 생성 시점을 분리해 최대 9초 기다리고 한 번만 실행한다. 찾지 못하면 화면에 **번역 다시 실행** 버튼을 제공한다. 검색은 전체 윈도우나 클래스 이름에 의존하지 않는다. OS가 이 시스템 UI 구조를 바꾸거나 번역을 지원하지 않는 텍스트인 경우 자동 실행에 한계가 있다.

## 로딩 개선

- URLSession의 바이트별 비동기 반복을 **데이터 청크 수신**으로 변경했다. 상태 코드·허용 호스트·리디렉션·전송량 제한은 유지한다.
- 동일한 이미지에 대한 동시 요청은 다운로드와 디코딩 작업을 공유한다. 한 화면이 취소되어도 다른 사용자가 기다리는 요청은 유지하고, 모든 사용자가 떠나면 취소한다.
- 현재 페이지를 먼저 로드한 후 다음 페이지와 직전 페이지를 미리 받는다. 미리 받기는 최대 2개씩 병렬 실행하며 이동 시 취소·교체한다.
- 이미지 다운로드와 ImageIO 디코딩은 메인 스레드 밖에서 수행한다. 디코딩한 이미지를 96MiB·48개 비용 제한 NSCache에 보관한다.
- 원본 이미지 전송 24MB·표지 2MB, 디코딩 긴 변 3000px·표지 480px 제한을 유지한다. 디스크에 읽기 이미지를 저장하지 않는다.

테스트에서 동시 요청 2개가 **1회 다운로드**를 공유했고, 미리 받기 완료 후 다음 페이지를 열 때 **추가 다운로드 0회**였다. 캐시 조회는 기기에서 약 0.005ms였지만, 이는 합성 데이터의 메모리 조회 시간이며 화면 전체 전환 시간이나 실제 네트워크 속도를 의미하지 않는다. 미리 받기 완료 전의 이동과 첫 요청은 서버·네트워크 속도에 영향을 받는다. NSCache 비용 제한은 전체 프로세스 메모리 상한을 보장하지 않는다.

## 코드 구조

경로는 `native-ios/NumberMemo/` 기준이다.

| 위치 | 역할 |
| --- | --- |
| `Core/Content/GalleryContent.swift` | 메타데이터·페이지 모델, 엄격한 JSON 래퍼 파싱, 경로·오류 |
| `Core/Content/ContentTransport.swift` | HTTPS·호스트·리디렉션 제한, 청크 단위 전송량 검사·취소 |
| `Core/Content/CDNRouting.swift` | 현재 `gg.js` 문법에서 호스트·경로 데이터 추출 |
| `Core/Content/HitomiContentSource.swift` | 목록·검색 인덱스, 메타데이터·이미지 요청, CDN 설정 갱신 |
| `Presentation/Content/PageImageStore.swift` | 요청 병합·취소, ImageIO 디코딩, 캐시·미리 받기 |
| `Presentation/Content/NativeContentView.swift` | 탐색·검색·작품 상세·그리드 북마크 |
| `Presentation/Content/NativeReaderView.swift` | 읽기 상태·퀵 메뉴·진행률·번역 연결 |
| `Presentation/Content/ReaderPagingView.swift` | 가로·세로 페이징, 연속 스크롤, 확대·탭 동작 |
| `Presentation/Content/ReaderPreferences.swift` | 읽기 설정·북마크 동작 |
| `Presentation/Content/ReaderSurfaces.swift` | 페이지 프리뷰·상세정보 |
| `Presentation/Content/ReaderTranslation.swift` | Apple Live Text 이미지 번역 및 제한된 자동 실행 |
| `Presentation/Works/WorkCardView.swift` | 보관함·둘러보기의 공통 카드와 열 수 규칙 |

원본 HTML이나 광고 스크립트를 로드·실행하지 않는다. CDN 설정은 문자열 데이터로 해석하며 문법이 바뀌면 오류를 반환한다. 기존 보관함 표지 큐는 별도 기존 클라이언트를 사용한다. 전체 앱의 트래픽 패킷 캡처는 수행하지 않았다.

검색은 공백으로 구분한 최대 8개 단어, `artist:`, `group:`, `series:`, `character:`, `tag:`, `type:`, `female:`, `male:`, `language:`와 `-` 제외 조건을 지원한다. 조건 값의 공백은 밑줄로 연결한다. 결과는 ID 내림차순이며 한 전체 목록의 데이터는 8MB로 제한한다. 원본 사이트의 모든 검색 제안·정렬을 재현하지 않는다.

## 실기기 검증

USB 연결 iPhone 17, iOS 27.2 (24B5089g), arm64에서 서명·설치·실행했다. 기존 bundle ID를 유지하며 실제 보관함을 UI 테스트에 사용하지 않는다. UI 검사는 합성 페이지와 메모리 DB, 별도 읽기 설정 저장소를 사용한다. 네트워크 통합 검사는 실제 CDN 이미지를 내려받아 디코딩하되 화면 캡처·저장소에 저장하지 않는다.

| 검사 | 최종 결과 | 범위 |
| --- | --- | --- |
| 기존 콘텐츠 검사 | 7개 통과 | 파싱, CDN 규칙, Range·바이너리 검증, 캐시 |
| 실제 CDN 통합 검사 | 1개 통과 | 목록·작품 2개의 첫/마지막 이미지·표지·WebP/AVIF·검색 |
| 읽기 UX 및 성능 단위 검사 | 7개 통과 | 요청 병합·개별 취소, 미리 받기, 청크 상한·HTTP 오류·취소, OCR, 공통 열 수, 중복 북마크 방지 |
| 실기기 UI 검사 | 5개 통과 | 그리드 길게 누르기·오류 재시도, 전체 화면·좌우 탭·확대·프리뷰·북마크·회전·앱 복귀·나가기, RTL·세로·연속 스크롤·하단 메뉴, 실제 번역·원문 복원, 이미지 실패 시 나가기 |

각 수정 뒤 해당 검사를 다시 실행한 **고유 검사 20개**의 최종 결과다. 모든 중간 실행이 성공했다는 뜻은 아니다. 초기 테스트에서 접근성 식별자가 부모에서 전파되던 부분을 수정했고, 복귀 애니메이션·스위치의 실제 터치 영역·연속 스크롤의 화면 밖 요소를 테스트가 올바르게 다루도록 수정했다. [현재 검증 요약](reader-ux-validation.json)과 [초기 구현 검증 요약](device-validation.json)을 구분해서 보관한다.

실행 결과 묶음은 검증 머신의 `/tmp/number-memo-reader-*.xcresult`에 있다. 상세 파일명은 현재 검증 요약에 기록한다. iOS 17 및 다른 iPhone·iPad·이동통신망, 긴 작품의 장시간 메모리 계측은 후속 검증 대상이다. CDN 형식이나 호스트가 바뀌면 어댑터 업데이트가 필요할 수 있다.

## 재실행

일반 `NumberMemo` 스킴에서는 외부 네트워크 통합 검사를 건너뛴다. `NativeContentDeviceValidation`은 실제 CDN 검사를 활성화한다. UI의 번역 검사는 합성 이미지에 실제 시스템 번역을 사용하므로 언어팩이 필요할 수 있다.

```sh
xcodebuild -project native-ios/NumberMemo.xcodeproj \
  -scheme NativeContentDeviceValidation -configuration Debug \
  -destination 'id=DEVICE_ID' -allowProvisioningUpdates \
  -parallel-testing-enabled NO \
  -only-testing:NumberMemoTests/NativeContentTests \
  -only-testing:NumberMemoTests/NativeContentLiveTests \
  -only-testing:NumberMemoTests/ReaderUXTests \
  -only-testing:NumberMemoUITests test
```

테스트 진입점과 합성 소스는 `DEBUG` 빌드에서만 활성화된다. Xcode 프로젝트와 `project.yml`의 앱·공유 확장·테스트 타깃을 유지한다.

## 탐색 및 읽기 확장 (2026-10-04)

- 언어와 최신/오늘/주간/월간/연간 인기순을 드롭다운으로 선택한다. 원본 `popular/{today,week,month,year}-{language}.nozomi` 순서를 유지하며, 검색 조건이 있으면 인기 목록 순서대로 교집합을 표시한다. 네 기간 모두 실제 CDN 응답과 기기 테스트를 확인했다.
- 서버 메타데이터의 `female`·`male` 플래그는 문자열 `"1"`, 숫자, Bool을 처리한다. 둘 다 있는 경우 양쪽 이름공간을 보존한다. 일반 태그에만 `tag:`를 사용한다. 언어·작가·태그 검색으로 진입할 때는 기본 한국어 필터를 중복 적용하지 않는다.
- 작품 정보와 읽기 상세정보의 작가·언어·태그는 버튼으로 검색한다. 읽기 상세에서 검색하면 시트를 닫은 후 검색 결과로 이동한다.
- 읽기 설정 배경은 불투명한 시스템 배경색이다. 진입 안내는 닫기/다시 보지 않기를 제공하며 읽기 설정과 기본 설정에서 언제든 다시 연다.
- 안전영역 밖에서 시작하는 아래 방향 드래그는 화면이 손가락을 따라 움직이며, 96pt 이상 내리거나 24pt 이상 이동 후 550pt/s 이상으로 빠르게 쓸면 작품을 닫는다. 기준 미만은 스프링으로 원위치에 돌아온다. 핀치와 시스템 안전영역 제스처는 종료 제스처와 구분한다.
- 번역은 원본 이미지에 Apple Live Text를 연결한다. 여러 페이지 화면에서는 현재 묶음의 첫 페이지를 대상으로 한다. 확대 후 자동 재분석은 안정성을 위해 제거했다. 번역 버튼으로 시작한 세션의 분석 결과를 유지한다.
- 여러 페이지 보기의 미리 받기는 현재 묶음에 필요한 페이지에 이어 설정한 수의 다음 페이지까지 포함한다. 원본 확대 OCR 이미지는 장기 캐시에 저장하지 않는다.

첫 번역 언어의 다운로드 확인창은 iOS가 표시할 수 있다. 글자 인식 품질과 지원 언어는 Vision 및 Apple Translation의 범위를 따른다.

## 탐색 및 읽기 화면 보완

- 탐색 카드의 좌측 상단에 흰색 북마크 아이콘을 표시한다. GRDB 관찰로 저장·삭제 결과를 반영하며, 다시 탐색으로 돌아올 때도 현재 보관함 상태를 표시한다.
- 탐색 상단은 폴더 탭과 같은 `LiquidGlassTitleCapsule` 및 투명 내비게이션 배경을 사용한다.
- 두 읽기 퀵 메뉴는 iOS 26 이상에서 실제 `glassEffect`를 사용한다. 아이콘과 라벨은 흰색이고, 상시 메뉴에도 작은 라벨을 표시한다. 이전 OS에는 material 대체 표시를 유지한다. [Apple Liquid Glass 문서](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views).
- 상단 안내 바는 화면 위 2pt, 폭 96pt, 높이 2pt로 옮겼다. 종료 스와이프는 거리·속도·방향을 함께 판단하며, 드래그 중 자동 넘김을 멈춘다.
- 번역의 배경과 텍스트 배치는 기존 인앱 브라우저와 같은 Apple Live Text로 대체했다. 앱에서 배경색을 샘플링하거나 흰 박스를 덧칠하지 않는다.

이번 UI 보완에서는 실기기 단위·UI 검사 29개와 Release 빌드를 통과했다. 기존 CDN 검사 2개를 포함한 누적 최종 결과는 31개이며, 실행별 결과는 `reader-ux-validation.json`에 기록했다. 합성 페이지의 두 퀵 메뉴·북마크 표시·상단 바·축소한 번역 박스를 기기 캡처로 확인했다.


## 새로고침 및 북마크 전환 수정

- 탐색 길게 누르기는 저장/해제를 전환한다. 읽기 화면의 기존 북마크 추가 동작은 유지한다.
- `GalleryFeedLoader`가 요청 수명을 소유한다. SwiftUI 새로고침 호출이 취소되어도 완료를 기다리며, 새로고침 시작 시 목록을 비우지 않는다. 실패하면 기존 결과와 재시도 버튼을 유지한다.
- 새로고침은 항상 offset 0에서 다시 시작한다. 검색 조건 변경은 이전 결과를 초기화하고, 이전 요청의 늦은 응답은 세대 토큰으로 무시한다. 실패 후 재시도는 실패했던 초기/추가 요청의 종류를 유지한다.


앞선 Live Text 복원 단계에서는 실기기 검사 31개(단위 23개, UI 8개)가 대상별 재실행을 거쳐 통과했다. 번역 검사는 시스템이 실제 표시한 한국어를 화면 캡처 OCR로 검사하고, 확대 후 250% 유지·재번역·원본 복귀도 확인했다. 확대 영역은 잘린 단어로 언어 판별이 실패하지 않도록 전체 줄 너비와 약간의 수직 문맥을 포함한다. 최종 Release 빌드도 통과했다. 이전 사용자 정의 렌더러의 두 단위 검사와 OCR 좌표 변환 검사는 해당 구현 제거에 따라 삭제했다. 실행별 성공/중간 실패 및 범위는 `reader-ux-validation.json`을 따른다.


## 번역 자동 실행 안정화 및 확대 이동 (2026-10-04)

- 분석 교체와 자동 번역의 경쟁을 없애기 위해 확대 후 재분석을 제거했다. 자동 실행 대기는 1.8초에서 최대 9초로 늘리고, 실행 가능한 메뉴 액션을 우선하며 선택된 번역은 다시 누르지 않는다.
- 번역 UI는 확대되는 이미지 대신 고정 캔버스에 부착한다. 확대/이동은 이미지 좌표만 바꾸고, 분석 횟수는 유지한다.
- 일반 읽기 확대는 상하좌우에 반 화면의 실제 스크롤 여백을 제공한다. 이미지보다 세로 공간이 큰 가로형 페이지도 위아래로 이동할 수 있다.
- 확대 중 부모 스크롤을 잠그고 축소/화면 이탈 시 이전 상태로 복원한다. 여러 페이지를 동시에 확대하면 마지막 확대 페이지가 축소될 때까지 부모 잠금을 유지한다. 확대된 페이지의 아래 방향 드래그는 작품을 닫지 않는다.
- 읽기 안내도 변경된 동작에 맞춰 수정했다.


현재 수정의 실기기 검사 36개(단위 26개, UI 10개) 및 Release 빌드가 통과했다. 일본어 페이지를 세 번 연속 열어 한국어 결과를 확인했고, 영어 번역 후 두 번 탭·드래그·핀치를 거쳐도 분석 횟수 1회와 시스템 버튼 표시가 유지되는 것을 검사했다. 가로형 짧은 페이지에서는 상하 이동 후에도 읽기 화면에 머물며, 축소 뒤 페이지 넘김과 나가기가 복구되는 것을 확인했다. 결과는 `/tmp/nm-stable-final.xcresult`, 마지막 대상별 재검증은 `/tmp/nm-stable-verification.xcresult`에 있다. 이전 자동 재분석 방식의 검증 기록은 과거 구현에 관한 것이며 현재 동작에는 적용하지 않는다.


## 폴더 이동·탐색 자동완성·이미지 안내 (2026-10-04)

- 폴더 작품 목록의 오른쪽 위 **빠른 이동(↕)** 메뉴에서 맨 위·맨 아래·저장한 달로 즉시 이동한다. 기존 저장순과 검색 결과를 유지하며, 선택한 달에 속하는 첫 작품으로 이동한다. 데이터베이스 형식이나 정렬은 변경하지 않는다.
- 탐색과 폴더는 같은 검색창 컴포넌트와 스크롤 표시 로직을 사용한다. 스크롤 이동량을 누적하여 아래로 32pt 이동하면 숨기고 위로 24pt 이동하면 다시 표시한다. 맨 위와 입력 중에는 검색창을 유지한다. 프레임당 이동량만 비교하던 방식에서 생기던 느린 스크롤·높은 화면 갱신율 문제를 수정했다. iOS 17에는 기존의 항상 표시하는 대체 동작을 유지한다.
- 자동완성은 [원본 검색 코드](https://ltn.gold-usergeneratedcontent.net/search.js)의 문자별 태그 인덱스 경로와 응답 형식을 사용한다. 전체 태그 목록이나 작품 메타데이터를 내려받지 않는다. 두 글자 이상 입력 후 300ms 대기하며 이전 작업을 취소하고, 결과는 최대 8개 표시한다. 응답은 64KB로 제한하며 64개 입력을 15분간 메모리에 캐시한다. 빈 결과도 캐시한다. 실패해도 직접 검색은 가능하다.
- 태그 선택은 마지막 입력 단어만 대체한다. 앞의 검색 조건, 제외 검색의 `-`, `female:`·`male:` 등 실제 이름공간을 보존하고 태그 내부 공백을 밑줄로 연결한다.
- 읽기 도움말은 실제 기기의 합성 페이지 스크린샷을 첨부하여 **내장 image_gen**으로 생성한 그림 위에 SwiftUI 한글 설명과 제스처 위치를 겹쳐 표시한다. 탭 / 확대·번역 / 나가기 세 화면으로 구성하며, 좌우 읽기 방향에 따라 이전·다음 라벨을 바꾼다. 닫기와 다시 보지 않기는 고정되어 있고 기존 설정에서 다시 열 수 있다. [생성 프롬프트와 이미지 출처](reader-guide-generation.json).
- 연결된 iPhone에서 단위 검사 16개, 실제 태그 서버 검사 1개, UI 검사 5개, 총 **22개**의 최종 결과가 통과했다. 120개 작품의 폴더 이동, 스크롤 검색창, 여러 조건을 유지하는 자동완성, 도움말 전환·재진입, 기존 북마크 토글·새로고침을 포함한다. Debug 실기기 및 Release 빌드가 통과했고, 테스트 인자 없이 앱을 다시 실행했다. [이번 변경 검증 기록](navigation-validation.json).

## 내장 브라우저 대체 모드 (2026-10-04)

- 기존 ‘앱의 읽기 화면으로 열기’ 설정을 **내장 브라우저에서 열기**로 바꿨다. 켜면 탐색 탭, 폴더 작품, 작품 상세의 읽기, 작가 바로가기를 모두 WKWebView로 연다. 끄면 기존 네이티브 탐색·읽기로 돌아온다.
- main의 이전 WKWebView 구현을 확인하고 기본 기능만 복원했다. 웹사이트 URL을 직접 열어 네이티브 목록·이미지 파서에 의존하지 않는다. 뒤로·앞으로·새로고침·닫기를 제공하고 사용자가 누른 새 창 링크는 같은 브라우저에서 연다. 탐색 탭에서는 하단 탭을 유지한다.
- 새 설정은 `use_embedded_browser`에 저장하며 기본값은 꺼짐이다. 네이티브/외부 Safari를 선택하던 이전 `use_in_app_browser`와 의미가 달라 이전 값을 이전하지 않는다. 영어·한국어·일본어 라벨과 설명을 추가했다.
- 실기기에서 단위 검사 19개, 실제 사이트 WebKit 로딩 검사 1개, UI 검사 3개가 통과했다. UI 검사는 메모리 DB와 로컬 합성 HTML을 사용하며 JavaScript, 설정 전환, 웹 탐색, 탭 복귀, 작품 주소와 닫기를 확인했다. 실제 사이트 검사는 문서 로딩만 확인하며 사이트 내용을 캡처하지 않는다.
- 최초 UI 실행은 iOS 자동화 초기화 시간 초과로 시작되지 못했다. UI만 재실행해 통과했고, 탭 복귀 시 현재 페이지와 탐색 기능을 유지하는 보완 후 해당 검사를 다시 통과했다. 최종 Debug 실기기 테스트와 Release 빌드를 통과했으며 일반 실행으로 복구했다. [검증 기록](browser-fallback-validation.json).
